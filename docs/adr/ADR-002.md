# ADR-002 — Use Azure SQL Ledger and content hashing for tamper-evident provenance

**Original status: Accepted**

**Primary quality attributes:** Integrity, auditability.

**Source image:** [page 2](../source-images/adr-page-2.jpg).

## Context
Disputes depend on whether evidence and event history can be trusted. Requirements: every event stores actor, timestamp, tenancy ID, source, status and content hash, and every simulated unauthorised edit must be detected.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| A. Normal tables with an audit column | Simple | Anyone with write access can alter history silently |
| B. Immutable blob storage only | Strong file immutability | No queryable event history; weak for relational state changes |
| C. Application-level hash chain | Portable | Custom code to build and trust; must be verified by us |
| D. Azure SQL Ledger append-only table plus SHA-256 hash of each attachment | Engine-enforced append-only, verifiable digests, relational queries | Ties provenance to Azure SQL; insert-only modelling |
| E. Blockchain service | Strong guarantees | Overkill, not in sandbox, higher complexity and cost |

## Decision — Option D
State changes are new rows, never updates. Attachment hashes are computed at intake and stored in the ledger. Verification recomputes blob hashes and runs ledger verification against stored digests before each report, on demand and nightly. Digests are exported automatically to an immutable Blob Storage container.

## Consequences

**Positive:** Tamper evidence is a platform feature, queryable with SQL, demonstrable with a test harness.

**Negative:** Current state must live in a separate mutable store (Workflow state). History can never be corrected, only superseded.

**Risks:** A database administrator with full access is still a trust assumption. Digests stored outside the database reduce that risk. **Detection, not prevention, is the claim.**

## Trade-off
Evidentiary strength versus modelling simplicity. Chosen compromise: separate current state from append-only history.

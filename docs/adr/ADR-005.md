# ADR-005 — Reject writes when the ledger is unavailable (fail closed)

**Original status: Accepted**

**Primary quality attributes:** Integrity over availability.

**Source image:** [page 4](../source-images/adr-page-4.jpg).

## Context
The integrity NFR says 100% of events carry actor, timestamp, tenancy ID, source, status and content hash. The ledger lives in the Evidence and Provenance Service, which can be unavailable while the workflow database is healthy. A write accepted in that window would exist without provenance and break the NFR.

## Options considered

| Option | Pros | Cons |
|---|---|---|
| A. Accept the event, write to ledger later | Higher availability | Events can exist without proof; gaps in record |
| B. Reject the write when the ledger cannot be reached | Every accepted event is provable | Users see errors during outages |

## Decision — Option B
Workflow retries three times with the same idempotency key, then returns 503 and does not accept the event. If the ledger entry is written but the state commit fails, the same key is retried and a reconciliation job reports orphan entries.

## Consequences

**Positive:** The integrity claim holds without exceptions.

**Negative:** Reduced availability for writes during Evidence Service or database problems.

**Mitigation:** The client keeps the draft and retries. Reads, timeline and existing reports are unaffected.

## Trade-off
Integrity versus availability. Integrity wins because the product exists to be a trustworthy record.
